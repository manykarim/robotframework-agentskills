## Why

Agents working on Robot Framework projects guess keyword signatures, grep `.robot` files to find tests, and add `Log` lines to debug failures. The `robotcode` CLI (2.7.0) covers all of these: discovery, libdoc, a stepwise REPL, a CLI debugger that pauses at failures with the browser still open, and result analysis. The experiment report in `docs/robotcodereports/robotcode-cli-report.md` (121 experiments) showed that these commands work for agent-driven use, but also found traps that stall or mislead an agent: a REPL hang under a PTY, a missing output directory that breaks Browser, `.save` keeping failed lines, and quoted `.break` names that never match. No existing skill teaches any of this, so agents don't use robotcode or use it wrongly.

## What Changes

- Add a new skill `rf-robotcode` at `skills/robotframework-robotcode-skill/`: a short router `SKILL.md` (question-to-command decision table, agent workflow, pipe/`--plain` rule, top traps), `references/` per task (setup and config, discover, run and wrapper, libdoc, repl, debug, results, analyze, agent mode, gotchas) and `assets/examples/` (`robot.toml` with profiles, `.robotrepl` scripts, a piped `(rdb)` command script).
- Mark version-specific limitations as "observed on robotcode 2.7.0" so they can be revisited when upstream fixes them.
- Complement, don't replace: `rf-robotcode` tells agents to prefer `robotcode` when it is on PATH and to fall back to the script-based skills otherwise. `rf-results`, `rf-libdoc-search` and `rf-libdoc-explain` each get one line pointing to `rf-robotcode`. Nothing is deprecated; the MCP server and the bundled Python scripts do not change.
- Extend the `UserPromptSubmit` context-injection hook so prompts that mention robotcode (and related terms such as `robot-debug`, `robot.toml`) trigger injection, and list `robotcode` among the available skills in the injected text.
- Add tests: structural checks for the skill, plus a CLI-fidelity test that checks every documented `robotcode` subcommand and flag against `robotcode … --help`, skipped when `robotcode` is not installed.
- Register the skill in the distribution tooling (`scripts/sync-skills.sh` name map → plugin `robotcode`, VS Code `rf-robotcode`, installer assets via the plugin mirror) and keep the drift check green.
- Before `references/analyze.md` is written, run a short spike to confirm `robotcode analyze code` behaviour (the report did not cover it).

Out of scope: an `rf-setup` install/setup skill (separate follow-up change), changes to the validation hooks (for example, using `analyze code` instead of or alongside robocop), and any deprecation of existing skills.

## Capabilities

### New Capabilities
- `robotcode-skill`: an agent skill that guides `robotcode` CLI use for discovery, documentation lookup, running, stepwise REPL work, debugging, result analysis and static analysis, including agent-safe invocation, version-stamped limitations, complementary cross-links to the script-based skills, prompt-triggered context injection, CLI-fidelity tests and drift-free distribution.

## Impact

- New: `skills/robotframework-robotcode-skill/` (SKILL.md, about 10 reference files, 4 example assets), `tests/test_robotcode_skill.py`.
- Edited: `skills/robotframework-results/SKILL.md`, `skills/robotframework-libdoc-search/SKILL.md`, `skills/robotframework-libdoc-explain/SKILL.md` (one cross-link each); `plugins/rf-agentskills/scripts/maybe_inject_rf_context.mjs` (regex + skill list); `tests/test_hook_scripts.py` (positive triggers); `scripts/sync-skills.sh` (name map).
- Generated by sync: `plugins/rf-agentskills/skills/robotcode/`, `vscode-extension/skills/rf-robotcode/`, `vscode-extension/package.json`, and the installer `_assets/` mirror at build time.
- Dependencies: none required at runtime. `robotcode[all]` is only needed locally or in CI to run the fidelity test, and to run the `analyze code` spike.
