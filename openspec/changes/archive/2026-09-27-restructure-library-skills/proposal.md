## Why

The five Gen-1 library skills (rf-browser, rf-selenium, rf-appium, rf-requests, rf-restinstance) are keyword catalogs: roughly 70% of their content is API knowledge the model already has, they offer menus instead of defaults, they contain no library-specific traps, and they never tell the agent how to check its own work. Each also ships a 340–606-line `references/keywords-reference.md` that duplicates libdoc and has already drifted into wrong or removed keywords. The Gen-2 skills (rf-robotcode, rf-setup, rf-platynui) show a better pattern: a decision table, one default with an escape hatch, a numbered workflow and inline traps. Once the correctness and install-guidance fixes land, the library skills should move to that pattern so they spend tokens on what the model gets wrong rather than on what it already knows.

## What Changes

- Define one **standard SKILL.md skeleton for library skills**, derived from the Gen-2 skills: orientation, the existing short `Installation` block (owned by `library-skill-install-guidance`), import and one recommended library configuration (with an escape hatch), a "which keyword/approach for which situation" decision table, a numbered agent workflow with a validate→fix loop, a **Gotchas** section, a gated "Read X when Y" reference table, and companion skills.
- Rewrite the five library `SKILL.md` files to that skeleton, removing generic explanations and keeping library-specific traps. Target: each `SKILL.md` ≤ 250 lines and ≤ ~3,000 tokens (measured reduction from today's 260–393 lines).
- The agent workflow in every library skill: check keyword signatures with libdoc (rf-robotcode `robotcode libdoc`, or the rf-libdoc script) → write → `robot --dryrun` → run → read results (rf-robotcode `results`, or rf-results) → fix.
- **BREAKING (content)**: delete `references/keywords-reference.md` from all five skills. Replace it with an instruction to query libdoc (`robotcode libdoc <Lib> list/show`, or the rf-libdoc script).
- Review every remaining reference file: keep, merge or delete each one (rationale per file in design.md); give every remaining reference over 100 lines a table of contents; keep references one level deep.
- Trim `assets/examples/` to runnable or dry-runnable suites in modern syntax (native `IF`/`FOR`, `VAR`, `RETURN`; no `Run Keyword If`), and make CI run `robot --dryrun` on each example whose library is importable.
- Style rules for library skills: explain *why* instead of using ALL-CAPS commands, use the same terms throughout, and include no time-sensitive statements beyond one "Verified against <library> <version>" line.
- Add structural tests that enforce the skeleton, the size budget, the missing catalog, the TOCs and the example dry-run.
- Sync the changes to the plugin and VS Code channels via `scripts/sync-skills.sh`.

Ordering: this change is implemented **after** `fix-library-skill-keyword-correctness` and `unify-library-install-guidance`, and **before or together with** `sharpen-skill-descriptions` (which owns frontmatter `description` text; this change leaves descriptions alone). It uses the skill name chosen by `merge-libdoc-skills` (`rf-libdoc`, archived) wherever it points to the libdoc script, and the `rf-<topic>` skill paths from `align-skill-names-with-spec`. It depends on `strengthen-skill-eval-harness` for with/without-skill baselines to show the rewrite helps and causes no regression.

## Impact

- **Skills (canonical)**: `skills/rf-{browser,selenium,appium,requests,restinstance}/` — `SKILL.md`, `references/*.md` (5 catalog files deleted, others merged, trimmed or given a TOC), `assets/examples/*.robot`.
- **Distribution copies**: `plugins/rf-agentskills/skills/rf-{browser,selenium,appium,requests,restinstance}/` and `vscode-extension/skills/rf-*/`, regenerated by `scripts/sync-skills.sh` (which already mirrors `references/` and `assets/` recursively, so deleted files disappear); `scripts/check-drift.sh` must pass.
- **Tests/CI**: new `tests/test_library_skill_structure.py`; `.github/workflows/ci.yml` gains a dry-run step for library examples (fail-soft library install, like the robotcode step).
- **Evals**: `eval/` tasks for the five skills are run through the harness from `strengthen-skill-eval-harness`; no harness changes here.
- **Hooks/MCP server**: no change expected; check that `plugins/rf-agentskills/scripts/maybe_inject_rf_context.mjs` and agent `.md` files do not name the deleted `keywords-reference.md`.
- **Users**: agents that loaded `keywords-reference.md` directly will query libdoc instead. This needs Robot Framework in the project environment (already required by rf-setup).
