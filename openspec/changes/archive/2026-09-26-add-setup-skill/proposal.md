## Why

Every skill in this repo assumes Robot Framework and its libraries are already installed in the right environment, but nothing teaches an agent how to get there. Agents fall back to a bare `pip install` into whatever Python is on PATH. That hits PEP 668 "externally managed" errors, installs into the wrong interpreter (robotcode, hooks and IDE then see different libraries), picks a Python that is too old for Browser, SeleniumLibrary, robotcode (3.10+), RESTinstance (3.11+) or PlatynUI (3.12+), and skips library post-install steps such as `rfbrowser init`. The SessionStart environment check already finds missing packages, but it only prints `pip install` lines and has no skill to point to.

## What Changes

- Add a new skill `rf-setup` at `skills/robotframework-setup-skill/`: a router `SKILL.md` (detect the existing tool from lockfiles, otherwise use uv; Python version guidance; a uv quick start; a library add-on table; verification steps) plus `references/` for uv, venv + pip, poetry, CLI tools (pipx / `uv tool`), per-library install and post-install steps, project layout, CI, and troubleshooting. `assets/examples/` holds ready-to-copy files: uv and poetry `pyproject.toml`, `requirements.txt`, `robot.toml`, a gitignore template, a smoke test and a GitHub Actions workflow.
- Every documented install recipe is run once in a scratch project before it is written down. Package versions and Python floors are stated with the date they were checked.
- Link to the library skills (`rf-browser`, `rf-selenium`, `rf-appium`, `rf-requests`, `rf-restinstance`, `rf-platynui`) and `rf-robotcode` for depth instead of duplicating them. `rf-robotcode`'s companion table points back to `rf-setup`.
- The `UserPromptSubmit` context text lists the setup skill. The SessionStart environment check's install hint points to `rf-setup` and shows the uv form next to pip.
- Tests: structural checks for the skill, and validity checks for the examples (TOML files parse, the smoke test passes `robot --dryrun`, the workflow YAML parses).
- Register the skill in `scripts/sync-skills.sh` (plugin name `setup`, VS Code `rf-setup`) and keep the drift check green.

Out of scope: changing which output channel the SessionStart hook uses. It writes to stderr, which Claude Code likely does not feed to the model. That needs its own change. Also out of scope: installing anything automatically; the skill guides the agent, it does not run installers.

## Capabilities

### New Capabilities
- `setup-skill`: an agent skill that guides Robot Framework environment and project setup with uv (preferred), venv + pip or poetry. It covers tool detection for existing projects, Python version floors, library-specific post-install steps, project layout, CI, verification and troubleshooting, with runnable examples, cross-links, hook mentions, tests and drift-free distribution.
