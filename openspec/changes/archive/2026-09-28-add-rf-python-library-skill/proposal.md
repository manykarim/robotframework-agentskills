## Why

No skill covers writing Robot Framework keyword libraries or listeners in Python, and the generator skills that touched keyword design are being retired (`retire-generator-skills`). Models write plausible library code that fails in ways that are specific to Robot Framework and silent: `@library` hides every method without `@keyword`, `from os.path import join` becomes a `Join` keyword, the default `TEST` scope throws state away between tests, `'Take ${qty: int} pears'` makes the whole library "contain no keywords", and `int | str` never converts `"10"`. The RF User Guide research (scratchpad `rf-guide-research.md`, sections A4 and B3) verified these on RF 7.4.2. A prototype checker confirmed that `robot.libdoc` plus a few `inspect`/`ast` checks can detect most of them before the agent runs a single test.

## What Changes

- Add a new skill `rf-python-library` at `skills/rf-python-library/` (directory name = `name`, per `align-skill-names-with-spec`). It contains:
  - A `SKILL.md` in the Gen-2 pattern: a default library template (`@library(scope=…, version=…)` class, `@keyword` methods, type hints, Google-style docstrings, `robot.api.logger`, `AssertionError`), decision tables (module vs class, scope chosen by state lifetime as the RF User Guide recommends, static vs hybrid vs dynamic), a conversion cheat sheet, an exceptions/logging table, placement and import rules (`libraries/` on the python-path, as rf-setup's project layout defines), a version gate, a numbered write → check → libdoc → pytest → dry-run → run workflow, and a Gotchas section with all 13 verified traps.
  - `references/`: `conversion.md` (built-in types, Enum/Literal/TypedDict, unions, custom converters), `api-variants.md` (module/class, dynamic and hybrid APIs, PythonLibCore, async keywords), `listeners.md` (listener v3, library as listener, priority), `communication.md` (exceptions, logging, threads, timeouts, `BuiltIn` access) and `packaging-and-docs.md` (libdoc, doc formats, versioning, package layout, tests).
  - `assets/examples/`: `ExampleLibrary.py`, a custom converter example, a listener example, and `.robot` suites that exercise them. CI runs these suites.
- Add a deterministic checker `scripts/check_library.py`. It loads a project library through Robot Framework's libdoc in a child process and reports, as bounded JSON: the keyword list and scope, the API style, and findings for import/init failures, keyword-creation errors, "contains no keywords", leaked keywords (source is not the library file), public methods hidden by `@library`, listener methods exposed as keywords, lost signatures (`*args, **kwargs` only), `str` inside a union, untyped or positional-only arguments, missing docs, output printed during import or init, broad `except` blocks, and state mutated in a `TEST`-scope class. It follows the script contract of `harden-skill-script-execution`: `uv run python`, PEP 723 metadata, exit codes 0/1/2/3/4, JSON only on stdout, `--help` with examples, bounded output and `--json-out`.
- Expose the checker as an MCP tool `rf_check_library` in `plugins/rf-agentskills/servers/rf-tools-server.py`. The tool always runs the checker in a subprocess in the project environment, because the checker imports user code.
- Security: the checker imports and instantiates user code. It only accepts libraries inside the project root, makes no network calls itself, runs the import in a child process with a timeout, and tells users to guard side effects with `BuiltIn().robot_running` / `dry_run_active`. Libdoc does not set `robot_running`, so guarded code stays inactive.
- Evals: three narrow tasks with objective graders and fixtures (Inventory state that must survive across tests, so the agent must choose `SUITE` or `GLOBAL` over the default `TEST` scope; `Set Mode` that accepts only ON/OFF through `Literal`/`Enum`; a listener that turns `flaky`-tagged failures into SKIP), plus a trigger query set with ≥ 8 should-trigger and ≥ 8 near-miss queries.
- Boundaries: the description and the Companion Skills table separate this skill from `rf-language` (change `add-rf-language-skill`: `.robot`/`.resource` authoring of tests, user keywords, resources and variables) and from the third-party library skills (using Browser, SeleniumLibrary, RequestsLibrary and so on). rf-setup's `project-layout.md` points to this skill for the `libraries/` folder.
- Distribution: sync to the plugin and VS Code channels, the installer assets, the `UserPromptSubmit` hook skill list, the README skill table, CI (examples run and checker tests) and a structural test file.

Ordering: implement after `retire-generator-skills`, `merge-libdoc-skills`, `align-skill-names-with-spec` and `harden-skill-script-execution` (the sync rules, the script contract and the MCP subprocess path exist), and after `add-rf-language-skill`. Descriptions and the companion catalogue follow `sharpen-skill-descriptions`. Trigger and task evals use the runner from `strengthen-skill-eval-harness`. If `rf-language` has not landed, the boundary text names only "`.robot`/`.resource` user keywords" and a follow-up adds the name.
